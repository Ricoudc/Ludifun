# Audit global du logiciel — novembre 2026

Troisième audit complet, à l'état de l'étape 5.74 (exercice neuf sur une erreur qui revient,
moteur 1.19.0, migration 0032). Les deux premiers (`audit-2026-09.md`, `audit-2026-10.md`)
s'arrêtaient à l'étape 30. Celui-ci porte sur ce que les règles du projet (`CLAUDE.md`) exigent
en permanence : séparation parent / enfant, données techniques seulement dans les journaux,
texte de leçon traité comme une donnée par l'IA, dépendances sans faille connue, cohérence entre
le code et la documentation. Règle inchangée : chaque erreur corrigée a un test qui la reproduit.

## 1. Méthode

| Volet | Ce qui a été fait |
|---|---|
| Outils automatiques | ruff, mypy strict, `flutter analyze`, tests serveur et application, audit des dépendances (pip-audit sur `uv.lock`, `flutter pub outdated`) |
| Dépôt | recherche de secrets, de fichiers `.env`, de photos et de leçons d'enfant suivis par git |
| Séparation | inventaire des routes par le schéma OpenAPI (110 opérations), comparé route par route à `tests/api/test_separation.py` |
| Journaux et suivi | relecture de tout ce qui finit dans le journal, dans `ai_runs.warnings` et sur `/suivi` : messages d'erreur des fournisseurs d'IA, sorties hors schéma, rejets du contrôle |
| Demandes à l'IA (§142-143) | relecture des neuf entrées construites pour l'IA : chaque texte venu d'une leçon, d'un enfant, d'un parent ou d'une page web est-il entre balises, sans pouvoir fermer la sienne ? |
| Coût et abus | plafond du jour et limites de débit sur chaque route qui appelle l'IA |
| Code récent | exercice ciblé (§5.74), fin de séance et tâches de fond, mot de Ludi, outils d'évaluation et de comparaison |
| Déploiement | en-têtes de sécurité (Caddy, pages web du serveur), secret par défaut refusé en production, documentation de l'API fermée en production |
| Scripts Windows | les 16 scripts `.ps1` : UTF-8 avec BOM, fins de ligne CRLF |

## 2. Résultat en bref

- **3 erreurs corrigées côté serveur**, toutes sur la protection des données : deux fuites de
  texte de leçon vers le journal et le suivi technique, une balise de leçon qu'un texte pouvait
  fermer.
- **4 dépendances mises à jour** (`pypdf`, `pillow`, `certifi`, `dnspython`) : 60 failles connues
  avant, aucune après.
- **Séparation parent / enfant : aucun trou trouvé.** Les tests ne couvraient qu'une partie des 110 routes ;
  ils les couvrent maintenant toutes, et un test échoue dès qu'une route nouvelle n'est rangée
  dans aucune liste.
- Tests : serveur 2 694, application 181. Tout passe ; ruff, mypy et `flutter analyze` ne
  signalent rien.

## 3. Erreurs corrigées

| # | Gravité | Où | Problème | Correction | Test |
|---|---|---|---|---|---|
| 1 | **Moyenne (données)** | fournisseurs d'IA compatibles OpenAI (Groq, Mistral, OpenRouter…) | En cas d'erreur, les 300 premiers signes de la réponse du service partaient dans le message d'erreur, donc dans le journal, dans `ai_runs.warnings` et sur `/suivi`. Or certains services joignent à l'erreur ce que le modèle venait d'écrire (`failed_generation` chez Groq) : **un morceau de la leçon de l'enfant**. | Seuls le code, le type et le message de l'erreur sont gardés (`error_detail`) ; une page d'erreur qui n'est pas du JSON reste lisible. | `test_openai_compatible.py` : « an error never carries what the model wrote » |
| 2 | **Moyenne (données)** | les trois fournisseurs (Claude, Ollama, compatibles OpenAI) | Une sortie hors schéma donnait le message complet de la validation, qui recopie la valeur refusée (« input_value=… »), donc du texte tiré de la leçon. La page `/suivi` l'enlevait à l'affichage, mais **le journal et la base le gardaient**. | Le message dit où et pourquoi (champ, type d'erreur), jamais la valeur ; une clé écrite par le modèle n'est pas recopiée non plus (`ports.schema_error`). | `test_openai_compatible.py` : « an out of schema answer is described without its text » |
| 3 | **Moyenne (§142-143)** | analyse de la leçon et préparation du matériel | Le texte de la leçon était placé entre `<lecon>` et `</lecon>` tel quel : une leçon contenant `</lecon>` fermait la balise, et la suite devenait une consigne possible pour l'IA. Même défaut pour la remarque du parent sur une image. Les autres entrées (réponse de l'enfant, devoir, pages web, remarque sur une notion) étaient déjà protégées. | Le chevron qui ouvre ou ferme une de nos balises devient « ‹ » (`text.neutralize_prompt_tags`) ; « 2 < 3 » et « 3<sup>e</sup> » ne changent pas, les extraits cités par l'IA se retrouvent donc toujours dans la leçon. Remarque du parent : chevrons neutralisés, comme ailleurs. | `test_prompt_fences.py` |

Les sorties de l'IA restent de toute façon contrôlées par le code (`app/domain/validation.py`) :
l'erreur 3 ne permettait pas d'enregistrer n'importe quoi, mais elle contredisait la règle
« texte de leçon = donnée, jamais consigne ».

## 4. Séparation parent / enfant : ce qui est maintenant testé

`tests/api/test_separation.py` range chaque route dans une liste :

| Liste | Routes | Ce qui est vérifié |
|---|---|---|
| `PARENT_ROUTES` | espace parent (tableau de bord, historique, export, contrôles, réglages de l'IA…) | sans jeton 401, appareil d'enfant 403, parent d'une autre famille 404 |
| `CHILD_ROUTES` | 25 routes qui désignent une leçon, une séance, un devoir ou une conversation | sans jeton 401 ; l'appareil d'un autre enfant, le parent d'une autre famille et un appareil qui demande l'enfant d'un autre reçoivent 404 ; après coup, la leçon, la séance, le devoir et la conversation visés sont intacts |
| `CHILD_SPACE` | `/v1/me`, mission, progression, listes | un appareil ne voit que son enfant, même s'il demande un autre `child_id` |
| `PUBLIC`, `SAME_SCOPE` | santé, inscription, connexion ; routes qui partagent la garde d'une route déjà testée | nommées une à une, pour qu'aucune ne soit « publique » par oubli |

Le test `test_every_route_is_in_a_separation_list` compare ces listes au schéma OpenAPI : une
route ajoutée sans y être rangée fait échouer la suite.

## 5. Points vérifiés, sans erreur

- **Dépôt** : aucun secret, `.env`, photo ni leçon d'enfant suivi par git ; `eval/` ne contient
  que les exemples ; `backend/.coverage` n'est plus suivi (reste de l'audit d'octobre).
- **Coût** : chaque route qui appelle l'IA passe par le plafond du jour (`ai_budget`) ou par une
  limite de débit par enfant ; l'exercice ciblé ne part pas si le plafond est atteint.
- **Rejets du contrôle** (`Rejection.element`, `reason`) : libellés techniques seulement
  (« questions[1] », « cloze »), jamais le texte de la question.
- **E-mails** : le corps d'un e-mail n'est écrit dans le journal qu'en dehors de la production.
- **Déploiement** : en-têtes de sécurité posés par Caddy et par les pages web du serveur ;
  documentation de l'API fermée en production ; secret de développement refusé en production.
- **Moteur** : seuils de décision dans `engine_rules.toml` (1.19.0), séances de référence
  identiques ; le mot de Ludi et l'exercice ciblé sont écrits ou contrôlés par le code.
- **Scripts Windows** : les 16 scripts sont en UTF-8 avec BOM et CRLF.
- **Migrations** : 0032 est la dernière ; `/health/ready` lit la version en base.
